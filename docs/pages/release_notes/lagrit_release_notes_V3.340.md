LaGriT V3.3.4 Release Notes (in development)
====================

This page collects the changes since the V3.3.3 release (tag V3.3.3, January 2024). V3.3.4 is not yet released: the CMake project version is 3.3.4, and entries are added as pull requests merge. Pull requests still in review are listed separately at the end.

Previous release  LaGriT V3.3.3  Jan 4, 2024

### New commands and options

- **improve_tets** (#296): improves the worst tetrahedra of a mesh, by quality = the smallest sine of the dihedral angles, with smoothing and flips that keep the vertex set (Klingner and Shewchuk, IMR 2007). Boundary and interface vertices slide in their plane or line; a pset limits the work. See IMPROVE_TETS.md.
- **quality / minsine** (#296): the smallest dihedral-angle sine of each cell.
- **cmo / addatt / edge_lengths_min, edge_lengths_max, edge_lengths_mean** (#300).
- **createpts / poisson_disk** in 3D (#290, Poisson 3D sampling), with input checks that stop with an error instead of crashing on bad 3D input (#302).
- **Input lines** up to 1024 characters (#299; 80 before). Longer lines are refused, and a token cut at 32 characters gives a WARNING.
- **examples/dfn_tets** (#304): scripts that build 3D Poisson disk tet meshes around a DFN.

### Fixes

- connect: a negative or huge imt is refused with an error instead of crashing (#297, issue #240).
- hextotet / grid2grid: prism to 14 (issue #214) and pyramid to 4 wrote past their arrays; options that do not fit the cells are refused (#298).
- eltset: inter and not with three or more sets gave wrong results without a message (#301). ELTSET2.md and PSET.md document the set logic.
- triangulate (issues #239, #57), a crash in cmo / copy (issue #6), macOS .stor output, the Poisson sampler, createpts checks (#292).
- interpolate and refine fixes (#293).
- Compiler fixes (#260, clang flag -Wno-error=implicit-int; #264).

### Build and tests

- CMake builds Exodus as an option; src/fc_mangle.h is generated by CMake and no longer tracked (#295).
- New test suite test/suite, with independent checks and a results page per suite, and CI that runs it (#294). `sh test/suite/run_all.sh` runs every suite; the level01 tests run inside it as test_lagrit_upstream. New suites since: test_avs_io (#305), test_hextotet (#298), test_set_logic (#301), test_edge_lengths (#300), test_input_lines (#299), test_improve_tets, test_element_angles and test_crush_thin_tets (#296).

### Changes in behaviour

- Input lines longer than 1024 characters are refused; before, characters past column 80 were dropped without a warning (#299).
- eltset inter and not with three or more sets now give the documented result (#301).

### In review (open pull requests)

- **2D connect: exact, complete and fast.** For points in a coordinate plane, 2D connect gives the exact Delaunay triangulation of the convex hull, and its time grows linearly with the number of points (256,000 random points: 1.5 s, was 35 s on a Mac). See [connect_notes](../docs/connect_notes.md).
  - #312 the enclosing triangle is placed inside the box far from the origin (UTM coordinates gave no triangles).
  - #313 exact in-circle and orientation tests (src/lg_predicates2d.c); the triangles along the convex hull are added and the mesh flipped to Delaunay (src/lg_connect2d_hull.c); connect no longer runs recon / 0 for such points. New suite test_connect_2d.
  - #314 more than 100 points are inserted in a BRIO order (src/lg_brio_order.c); new option **connect / old_order** keeps the earlier order.
  - Changes users will see: a few more triangles along the hull; where points are exactly cocircular (a regular grid) a square may be split along the other diagonal; two new lines in connect's output. level01 references updated: connect_errors, intersect, intrp_2D_sizes, pflotran_stor, recon1.
- **3D connect insertion order** (branch connect3d-brio, on top of #314): more than 100 points inserted in a 3D BRIO order (lg_brio_order3); `old_order` works in 3D too; the vertex-type test `itsttp` has a fast path for the names asked most, and 3D connect tests interfaces once per vertex. 256,000 random points: 2.7 s, was 14.0 s (whole run, Linux sandbox); 3D growth N^1.05 to N^1.10 for every input order (was up to N^1.3). Meshes change only where points are exactly cospherical (a cube of a regular grid splits into 5 or 6 tets, either Delaunay); level01 references updated for that: addmesh_add, cmo_addatt_normals, connect_cube, hybrid_volume, rmpoint, setpts, smooth. Also fixed there: delaunay.f and delaunay2d_lg.f sized a work array by nnodes, but points added by fix_small_tets / fix_small_triangles_lg are numbered above it, so connect wrote past the array (MMVERIFY "Array epilog overwritten", then a stop; seen with all points on a sphere).
- **connect options** (#317, on top of connect3d-brio): **noadd**, **check_interface** and **old_order** may be anywhere in the command, in 2D and 3D, in any combination (before: noadd and check_interface only as the last token in 3D, so not both; noadd only as token 18 in 2D, so `connect / noadd` added points in 2D). A point range or pset right after connect (`connect / 1,0,0`, `connect / pset,get,name`, as CONNECT1.md shows) is read as the point range (before: no tets, or every point connected). The coordinates of the enclosing tetrahedron or triangle are deprecated (a WARNING); fewer than 12 (3D) or 9 (2D) numbers after the point range give a WARNING and are ignored (before: 12 numbers were read whatever was there, so `connect / delaunay / 1,0,0 / noadd` made no tets). check_interface in 2D gives a WARNING. New suite test_connect_options (11 of its 20 decks fail with V3.3.4).
- #315 recon accepts vertices with imt 0 (no more "MMGETBLK: ERROR! FATAL ... matrecon").
- #303 createpts / poisson_disk / 3d_box: h_lookup octree, a lean octree for the h field and the neighbour search, with a maximal fill.
- #306, #307, #308 read / avs and dump / avs: errors instead of crashes and wrong meshes; restructured code; read about 3 times and dump about 2.5 times faster, output byte-identical. read / avs requires a named, empty mesh object (to join meshes, use addmesh / append).

### Known issues

- 3D connect: not exactly Delaunay where points are nearly cospherical (a grid jittered by 1e-9: 2,977 faces), and thin tets along the convex hull are lost with the enclosing tetrahedron (1.3% of the hull volume for random points, 5.4% for a 100 x 1 x 1 box). Exact 3D tests and a hull fill are planned.
- 2D connect of points in a tilted plane still uses the tolerance tests and recon / 0.
